# Buyer reviews: F-1401 and F-1403

Delivered orders at `/account/orders/:id` show one form per distinct purchased product. Completed bookings at `/booking/confirmation/:id` (or `?id=`) show package/experience and guide forms, deduplicated by target type and ID. Hotels and transport have no review target in the existing API and are omitted. Bookings get an independent, fresh, authenticated ownership check before any form appears. No new route or API contract is introduced.

Submission uses `POST /api/v1/reviews` with `targetType`, `targetId`, exactly one `orderId`/`bookingId`, a selected rating from 1 to 5, and an optional trimmed comment. Comments are limited to 2,000 characters in the form; they are public. The client validates the server confirmation against the current buyer, target, rating, UUID and timestamp. HTTP 409 displays the one-review-per-item rule; 422 displays ineligibility; 401/403/404 require renewed account/purchase verification. Uncertain submissions retain the in-memory draft for explicit retry; the existing database unique constraint prevents duplicates across retries or tabs. No automatic retry, offline queue or draft persistence is used.

Drafts and request lifetimes are scoped to the current authentication revision and purchase target. Requests abort on unmount or session/target change; stale responses cannot confirm a review in the next account. Submission times out after 25 seconds. A labeled native rating select and textarea support keyboard use; completion/error feedback receives focus. New strings have scoped English/Amharic resources. Other language translations remain with their allocated owner.

Backend prerequisite commit `b431e6b` requires COMPLETED bookings (CONFIRMED no longer qualifies), exactly one proof reference, and a target belonging to the owned purchase. Existing delivered-order, ownership, duplicate checks and PostgreSQL reviewer/target uniqueness remain authoritative. Enterprise targets remain supported by the backend; this task exposes item reviews only. No migration was needed.

Verification: 44 focused frontend cases cover eligibility, duplicates, invalid confirmations, explicit retry, timeout, duplicate clicks, target/account changes and late responses. Nine backend eligibility cases and five PostgreSQL workflow cases passed with the prerequisite commit. Firefox at a 360 × 800 CSS viewport verifies actual order and booking routes against isolated MSW demo fixtures, keyboard submission, confirmation focus, offline blocking, duplicate rejection after remount, no horizontal overflow and zero review-form axe violations. Browser artifacts are in ignored `.tmp-verification/f1401-*`; these checks do not submit live reviews.

Mock-only example URLs: `/account/orders/aaaa0000-0000-4000-8000-000000000004` and `/booking/confirmation/bbbb0000-0000-4000-8000-000000000003`, signed in as the demo buyer. Fixtures are isolated from existing checkout, cancellation and refund examples. Review state lasts for the current mock app instance.

F-1402 (My reviews) remains separate. The existing API has no authenticated reviewer-scoped list endpoint; add and verify that contract before implementing a private review list. Public testimonials are not an authoritative source for the user's full review history, because moderated/private reviews may be absent.
